Datenbank für den CentralPoint einrichten

Letzte Änderung 29.08.2026 · Version 1 · Seiten-ID 719

Entwurf – diese Seite ist noch nicht geprüft und kann Fehler enthalten.

Der CentralPoint bringt keinen Datenbankserver mit. MariaDB muss vorher installiert, ein Schema und ein Benutzer angelegt sein — erst danach lässt sich der CentralPoint verbinden.

In dieser Datenbank laufen die Stammdaten und die Bewegungsdaten aller angeschlossenen Kassen zusammen.

Voraussetzungen

  • Ein Server nach ITR Partner Service → Betrieb & Administration → Systemvoraussetzungen.
  • Mindestens MariaDB 10.11.4 oder die jeweils aktuellste Build-Version. Version 11.8 LTE ist noch nicht freigegeben.

MariaDB installieren

  1. MariaDB von https://mariadb.org laden — die 64-Bit-Fassung, und keine Alpha- oder Betaversion.
  2. Setup ausführen und dem Installationsdialog folgen.
  3. Das vergebene Kennwort des Benutzers root notieren. Ohne dieses Kennwort ist die Datenbank später nicht administrierbar.

HeidiSQL wird zusammen mit MariaDB installiert und dient im Folgenden als Oberfläche.

Schema anlegen

  1. HeidiSQL öffnen und über new unten links eine Sitzung anlegen: Sitzungsname, unter Hostname/IP entweder localhost oder die IP des Datenbankrechners, als Benutzer root mit dem bei der Installation vergebenen Kennwort.
  2. Open öffnet die Sitzung.
  3. Rechtsklick auf die Sitzung → Create new → Database.
  4. Namen des Schemas eingeben, üblich ist goodcompany.
  5. Collation auf latin1_german_ci stellen.
  6. Mit OK bestätigen.

Datenbankbenutzer anlegen

  1. In HeidiSQL das Benutzer-Symbol anklicken.
  2. Add wählen.
  3. Unter User Name den Namen eintragen, üblich ist goodcompany.
  4. Unter From Host den Wert % eintragen, damit der Zugriff nicht auf einen Rechner beschränkt ist.
  5. Ein Kennwort vergeben. Es wird bei der Verbindung des CentralPoint gebraucht — notieren.
  6. Häkchen bei Global Privileges setzen und über Add Object die freigegebenen Bereiche bestimmen; für vollen Zugriff wieder %.
  7. Mit OK abschließen.

Ergebnis prüfen

Das Schema erscheint in HeidiSQL, und eine neue Sitzung mit dem angelegten Benutzer öffnet sich ohne Fehler.

Konfigurationsdatei my.ini

Änderungen an my.ini gehören in die Hand von Datenbankfachleuten. Falsche Werte können die Datenbank unbrauchbar machen oder zu Datenverlust führen. Im Zweifel den ITR-Support hinzuziehen.

Eine Grundkonfiguration für den Betrieb mit dem CentralPoint:

[mysqld]
sql_mode="STRICT_TRANS_TABLES,NO_ENGINE_SUBSTITUTION"
max_allowed_packet=64M
open_files_limit=100000
transaction-isolation=READ-COMMITTED
binlog_format=ROW
[client]
port=3306
Parameter Wirkung
max_allowed_packet maximale Paketgröße, 32 oder 64 Megabyte
open_files_limit Anzahl gleichzeitig geöffneter Dateien
transaction-isolation=READ-COMMITTED sperrt bei Transaktionen einzelne Zeilen statt ganzer Tabellen

Auf Servern mit reichlich Arbeitsspeicher lassen sich zusätzlich Puffergrößen erhöhen — etwa query_cache_size, table_cache, key_buffer_size, sort_buffer_size und tmp_table_size.

[OFFEN: konkrete Puffergrößen je Installationsgröße. Die vorliegende Quelle stammt aus der Zeit von MariaDB 5.5, ihre Werte und Erläuterungen widersprechen sich teilweise und sind für MariaDB 10.11 nicht ohne Prüfung übertragbar.]
