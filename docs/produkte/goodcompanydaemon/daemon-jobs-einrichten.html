Daemon Jobs einrichten

Letzte Änderung 28.08.2026 · Version 1 · Seiten-ID 698

Entwurf – diese Seite ist noch nicht geprüft und kann Fehler enthalten.

Ein Daemon Job ist ein Auftrag aus Kommandos, den der Daemon zeitgesteuert oder direkt nach einem Import ausführt. Damit entstehen Exporte, Dateiumbenennungen und Nachverarbeitungen.

Voraussetzungen

  • Der Daemon ist eingerichtet und die Datenbankverbindung funktioniert
  • Für Exporte: Schreibrechte im Zielverzeichnis

So gehen Sie vor

  1. Öffnen Sie im Hauptfenster Jobs.
  2. Legen Sie einen Job an und füllen Sie die Felder:
Feld Bedeutung
Daemon Job Name frei wählbare Beschreibung des Auftrags
Ausführungstage Wochentage, an denen der Job laufen darf
Ausführungszeiträume Zeitsteuerung nach Jahr, Monat, Tag, Stunde, Minute
Kommandos Folge von Kommandos, jeweils mit Semikolon getrennt
Direktstart Job läuft automatisch, sobald eine Importdatei verarbeitet wurde
  1. Speichern Sie den Job.
  2. Zum sofortigen Prüfen: Rechtsklick auf den Job, Starten (Direkt) — dabei werden die Ausführungstage ignoriert.

Zeitsteuerung

Stehen in allen Spalten Sternchen, läuft der Job jede Minute. Eine 5 in der Spalte Minute bedeutet: zur fünften Minute jeder Stunde.

Ein Intervall wie „alle 5 Minuten" ist nicht möglich. Die Zeitsteuerung nennt feste Zeitpunkte, keine Abstände. Für kurze Abstände mehrere Zeitpunkte eintragen.

Bei aktivem Direktstart werden die Ausführungszeiträume ignoriert — der Job hängt dann am Import, nicht an der Uhr. Der Knopf Vorverarbeitung jetzt starten führt alle als Direktstart markierten Jobs aus.

Kommandos

Erlaubt sind SQL-Anweisungen und Dateioperationen:

Aufgabe Syntax
Datei löschen delete file: <filename>
Datei umbenennen rename file: <quelle>,<ziel>
Datei verschieben move file: <quelle>,<ziel>
Datei kopieren copy file: <quelle>,<ziel>
Dateien zusammenführen join files: <quelle1>,<quelle2>,<ziel>
Datei erstellen touch file: <filename>

Bei join files müssen Quelle 1, Quelle 2 und Ziel unterschiedliche Dateien sein. Ist das Ziel gleich einer Quelle, ist das Ergebnis unbrauchbar.

Variablen

Variable Bedeutung
###UNIXTIMESTAMP### Zeit in Millisekunden seit 01.01.1970
###TODAY### aktuelles Datum, yyyy-MM-dd
###YESTERDAY### gestriges Datum
###TOMORROW### morgiges Datum
###TIMESTAMP### Datum und Uhrzeit, yyyy-MM-dd_HHmmss_S
###LASTEXECUTIONDATE### Datum der letzten Ausführung
###CURRENTEXECUTIONDATE### Datum, für das der Job aktuell läuft
###EXEC_UNIXTIMESTAMP### Ausführungszeit in Millisekunden
###EXEC_TIMESTAMP### Ausführungsdatum und -uhrzeit
###ESC_SEMICOLON### Ersatz für ein Semikolon innerhalb eines Kommandos

Datumsplatzhalter nehmen ein eigenes Format auf, zum Beispiel ###LASTEXECUTIONDATE_yyyyMMdd###.

Ein Semikolon im SQL-Text muss als ###ESC_SEMICOLON### geschrieben werden — sonst endet das Kommando an dieser Stelle.

Beispiel: Export mit Zeitstempel

SQL
SELECT vorname, nachname INTO OUTFILE 'C:/export/teil1_###UNIXTIMESTAMP###.txt'
  FIELDS TERMINATED BY '\t' LINES TERMINATED BY '\n'
  FROM mitarbeiter WHERE vorname LIKE 'J%';

Anschließend lassen sich die erzeugten Dateien im selben Job zusammenführen:

Text
join files: 'C:/export/teil1.txt','C:/export/teil2.txt','C:/export/gesamt.txt';

Schleifen

Kommandos lassen sich für mehrere Werte wiederholen — etwa je Kasse ein Export.

Feste Werteliste:

Text
LOOP-START: @NUMBER : 1,2,3,4,5;
SELECT @NUMBER;
LOOP-END;

Werte aus einer Abfrage:

SQL
LOOP-START: @CRNR : SELECT DISTINCT(CR_ID) FROM ipos_cashregister c WHERE c.Deleted = FALSE;
SELECT @CRNR;
LOOP-END;

Der aktuelle Wert steht in der Variablen und kann in den Kommandos innerhalb der Schleife verwendet werden, zum Beispiel im Dateinamen des Exports.

Ergebnis prüfen

  1. Job über Starten (Direkt) ausführen.
  2. Protokoll öffnen — dort steht, ob der Job gelaufen ist und welche Kommandos fehlschlugen.
  3. Zieldatei im Export-Verzeichnis auf Inhalt und Zeitstempel prüfen.

Wenn es nicht funktioniert

  • Kommando endet vorzeitig: nach einem Semikolon im SQL-Text suchen und durch ###ESC_SEMICOLON### ersetzen.
  • Keine Zieldatei: Schreibrechte des Daemon-Kontos im Zielverzeichnis prüfen. Läuft der Daemon als Windows-Dienst, hat das Dienstkonto andere Rechte als der angemeldete Benutzer.
  • Job läuft nicht zur erwarteten Zeit: prüfen, ob Direktstart gesetzt ist — dann gelten die Zeiträume nicht.
