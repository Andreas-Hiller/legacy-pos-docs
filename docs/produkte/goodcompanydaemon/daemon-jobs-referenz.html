Daemon Jobs: Referenz

Entwurf – diese Seite ist noch nicht geprüft und kann Fehler enthalten.

Letzte Änderung 29.08.2026 · Version 1 · Seiten-ID 785

Alle Jobs, die in einem Daemon Job über call: aufgerufen werden können, mit ihren Parametern. Wie ein Daemon Job angelegt, zeitgesteuert und geprüft wird, steht in ITR Partner Service → Produkte → GoodCompanyDaemon → Daemon Jobs einrichten.

Aufrufform: call:<Jobname> gefolgt von den Parametern, je Parameter eine Zeile mit vorangestelltem #. Mehrere Kommandos in einem Job werden mit Semikolon getrennt.

Import von Stammdaten

VectronIPOSImporter

Importiert beliebige Stammdaten aus dem Vectron-Format. Beim Import wird je Feld geprüft, ob sich der Wert geändert hat — dadurch ist ein partieller Import möglich, ohne andere gepflegte Daten zu überschreiben.

Parameter Beschreibung Standardwert Werte
validForImport Auswahl der zu importierenden Datentypen; verkürzt die Laufzeit alle mainGroup, warenGruppen, Operators, Articles, Customers, Orders
objectProperties Definitionsdatei für Feldzuordnungen und Parameter – vollständiger Pfad
configFileOrders Konfigurationsdatei für Bestellungen – vollständiger Pfad

Die Definitionsdatei enthält Wertepaare Property=Feldnummer, jede Zeile mit dem Prefix des Datentyps (Article., Customer., Operator., Group., MainGroup., Order.).

Die früheren Parameter prefixDallasKey, suffixDallasKey, passwordTemplate, createOperatorsForAllBranches, roleMappings, ignoreZeroValues, operatorProperties und filePriceModifier wurden in die objectProperties verschoben.

Voraussetzung bei Daten aus Zuliefersystemen ist die Zuordnung von Kassen zu Filialen — siehe ITR Partner Service → Produkte → GoodCompanyDaemon → Filialüberwachung und Timer einrichten.

CSVConverter

Bringt Stammdaten im CSV-Format (Hauptgruppen, Warengruppen, Kunden, Artikel, Bediener) in ein Vectron-Format, das der VectronIPOSImporter anschließend verarbeitet.

Parameter Beschreibung Werte
csvProperties Pfad zur Konfigurationsdatei vollständiger Pfad

Einträge der Konfigurationsdatei, je Stammdatum mit Prefix (etwa Customer.):

Eintrag Beschreibung Werte
ImportMode Behandlung vorhandener Daten R ersetzen, A hinzufügen
IgnoreLines Zeilen am Anfang überspringen 1–999
FieldDelimiter Feldtrenner ; oder ,
FieldQuote Anführungszeichen "
Charset Zeichensatz der Quelldaten z. B. Cp1252
FilePathIn Quelldatei vollständiger Pfad
FilePathOut Ausgabedatei vollständiger Pfad
<Feldname> Spalte für das Feld; mehrere kommagetrennt 1–50

Stammdaten verteilen

CopyObjectsToBranches

Kopiert Stammdaten von einer Filiale auf andere. Derzeit möglich sind Artikel und Bediener.

Parameter Beschreibung Standardwert Werte
frombranch Quell-Filiale 0 0–999
tobranches Ziel-Filialen, kommagetrennt – 1–999
updateolddata vorhandene Einträge überschreiben false true, false
objects welche Daten kopiert werden – operators, articles
operators.excludedfields Felder beim Aktualisieren von Bedienern ignorieren – Feldnamen
articles.excludedfields Felder beim Aktualisieren von Artikeln ignorieren – Feldnamen
articles.includefields Felder explizit kopieren – Feldnamen
copyBarCode Barcode des Mitarbeiters als Kunden-Barcode kopieren false true, false
copyRfidCode RFID des Mitarbeiters als Kunden-RFID kopieren false true, false

Mit updateolddata=true werden vorhandene Einträge in den Ziel-Filialen überschrieben. Preise und Bezeichnungen, die dort abweichend gepflegt sind, gehen dabei verloren — sie werden über articles.excludedfields ausgenommen.

Bediener und Kunden ableiten

BZ2IposOperators

Legt Mitarbeiter aus der BrotZEIT als Bediener an.

Parameter Beschreibung Standardwert Werte
passwordtemplate Vorlage für die Passwortgenerierung operatorno operatorno, birthday:<Datumsformat>
resetallpasswords Passwörter zurücksetzen false true, false
createOperatorsForAllBranches Bediener für alle Filialen freischalten; setzt die Kassen-Filial-Zuordnung voraus false true, false
useTerminalTagsAsRFID Transponder als RFID hinterlegen false true, false
useMitarbeiterNrKasse MitarbeiterNrKasse statt Personalnummer als Bedienernummer false true, false
deactivateCustomersWhereBZOperatorInactive Kunden inaktiv schalten, wenn der Mitarbeiter inaktiv ist false true, false
deactivateOperatorWhenBZOperatorInactive Bediener inaktiv schalten, wenn der Mitarbeiter inaktiv ist false true, false

Regeln beim Import:

  • Ein Mitarbeiter wird nur importiert, wenn er mindestens einer Arbeitsstätte im Einsatzmodell zugeordnet ist.
  • Die Kassen der Filialen müssen noch nicht online sein.
  • Ist der Status nicht aktiv, wird der Bediener in der Kasse als gelöscht markiert und kann sich nirgends mehr anmelden.
  • Ist eine früher zugeordnete Filiale nicht mehr zugeordnet, wird der Bediener für diese Filiale gesperrt.
  • Voraussetzungen am Mitarbeiter: MitarbeiterNr. KASSE gesetzt, Arbeitsstätten per Einsatzmodell hinterlegt, Personalnummer ungleich 0.

Rollen aus den Kassenrechten des Mitarbeiters: EMPLOYEE, OPERATOR, SUPERVISOR, BRANCH_MANAGER, ADMIN.

Bei passwordtemplate=birthday:<Datumsformat> sind alle gültigen Datumsformate zulässig; das Passwort entsteht aus dem Geburtsdatum im angegebenen Format.

Operator2Customer

Legt angelegte Bediener zusätzlich als Kunden an. Übernommen werden nur Bediener im angegebenen Nummernbereich. Existiert bereits ein Kunde mit der Bedienernummer, werden Vor- und Nachname geprüft und angepasst.

Parameter Beschreibung Standardwert Werte
CustomerNoOffset auf die Bedienernummer aufaddierter Wert 0 0–999999
minValueForCustomerNo niedrigste zu übernehmende Bedienernummer 0 0–999999
maxValueForCustomerNo höchste zu übernehmende Bedienernummer 0 0–999999
customertags Tags für neue Kunden, kommagetrennt – Tagnamen
reactivateCustomers inaktive Kunden reaktivieren false true, false

Bestände und Konten

VectronStockImporter

Übernimmt aus dem 121er Vectron-Bericht Liefermengen als Lagermengen.

Parameter Beschreibung Standardwert Werte
stockField Feldzuordnung des Lagerwerts; mehrere kommagetrennt – z. B. 104_30_1
outputPath Differenzdatei für Fälle mit Ausgangsmenge ungleich 0, die überschrieben werden soll – vollständiger Pfad
replace Lagerwerte überschreiben; false addiert true true, false
addTag bei Artikeln mit diesem Tag immer addieren – beliebiger Tag
replaceTag bei Artikeln mit diesem Tag immer ersetzen – beliebiger Tag

LoadPrePayAccountValues

Importiert Bestände für PrePay-Konten. Im Modus REPLACE wird der Kontostand auf den Wert aus der Datei gesetzt, im Modus ADD addiert. Die Importdatei muss RFID, Barcode oder Kundennummer sowie eine Spalte mit dem Kontostand enthalten. Vor dem Import wird die Datei mit Zeitstempel umbenannt; das verhindert einen doppelten Import.

Parameter Beschreibung Standardwert Werte
filename Importdatei – vollständiger Pfad
mode Verarbeitungsmodus – REPLACE, ADD
key Suchschlüssel für das Konto – RFID, CUSTOMER_NUMBER, BARCODE
skipLine Zeilen am Anfang überspringen 0 Ganzzahl
posCustomerNumber Spalte Kundennummer – Ganzzahl
posRFID Spalte RFID-Code – Ganzzahl
posBarCode Spalte Barcode – Ganzzahl
posValue Spalte Kontostand – Ganzzahl

Drei Jobs exportieren im KAKOM-Format:

Job Inhalt
ExportKakomTransSal Filialreportdaten
ExportKakomClerkSal Bedienerumsatzdaten
ExportKakomTimedetcSal An- und Abmeldedaten der Bediener
Parameter Beschreibung Standardwert Werte
filename Ausgabedatei – vollständiger Pfad

Freie SQL-Verarbeitung

ExecuteSql

Führt eine SQL-Anweisung aus. Übergeben wird sie im Parameter sql. Typisch ist die Kombination aus vorherigem delete file: und einem SELECT ... INTO OUTFILE, um eine Exportdatei neu zu erzeugen.

Ein Semikolon im SQL-Text beendet das Kommando. Semikolons innerhalb der Anweisung müssen als ###ESC_SEMICOLON### geschrieben werden.

Die Syntax für Dateioperationen, Variablen und Schleifen steht in ITR Partner Service → Produkte → GoodCompanyDaemon → Daemon Jobs einrichten.
