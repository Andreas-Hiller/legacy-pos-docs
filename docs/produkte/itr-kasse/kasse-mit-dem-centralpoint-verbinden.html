Kasse mit dem CentralPoint verbinden

Entwurf – diese Seite ist noch nicht geprüft und kann Fehler enthalten.

Letzte Änderung 29.08.2026 · Version 1 · Seiten-ID 723

Ist die Kasse mit dem CentralPoint verbunden, bezieht sie ihre Stammdaten von dort und liefert ihre Belege dorthin zurück.

Mit dem Verbinden werden das Anlegen und Bearbeiten von Stammdaten an der Kasse gesperrt. Ab diesem Zeitpunkt werden Artikel, Warengruppen und Bediener ausschließlich im CentralPoint gepflegt.

Voraussetzungen

  • Ein installierter CentralPoint mit initialisierter Datenbank.
  • Adresse, Port, Schema, Benutzer und Kennwort der zentralen Datenbank.
  • Die zentrale Datenbank ist von der Kasse aus über Port 3306 erreichbar.

So gehen Sie vor

  1. An der Kasse ins Admin-Panel wechseln.
  2. Einstellungen → Zentrale DB öffnen.
  3. Filiale mit zentraler Datenbank verbinden aktivieren.
  4. Die Verbindungsparameter eintragen:
Feld Inhalt
Datenbanktyp fest MySQL
Datenbank URL IP des Rechners mit der zentralen Datenbank
Port Standard 3306
Database Name Name des Schemas, üblich goodcompany
Benutzer Datenbankbenutzer
Passwort dessen Kennwort

Die Werte müssen exakt denen aus der Datenbankeinrichtung entsprechen.

  1. Verbindungstest ausführen.
  2. Speichern drücken.

Die Datenbankparameter werden — anders als die übrigen Kasseneinstellungen — erst mit Speichern übernommen. Wer den Dialog ohne Speichern verlässt, verliert die Eingaben.

Synchronisationsintervalle

Getrennt einstellbar für beide Richtungen:

  • Synchronisation Stammdaten — Empfang der im CentralPoint gepflegten Daten.
  • Synchronisation Bondaten — Übergabe der Kassendaten an den CentralPoint.

Üblicherweise erreichen die Daten die zentrale Datenbank innerhalb von etwa 600 Sekunden, je nach eingestelltem Intervall.

Ergebnis prüfen

  • Der Verbindungstest bestätigt die Verbindung.
  • Eine im CentralPoint geänderte Stammdatenangabe erscheint nach einem Synchronisationslauf an der Kasse.
  • Ein an der Kasse erzeugter Beleg taucht im CentralPoint auf.

Wenn es nicht funktioniert

Schlägt die Synchronisation fehl, zeigt die Kasse eine Meldung. Häufige Ursachen:

Meldung Ursache
Hostname kann nicht aufgelöst werden Namensauflösung im Netz, IP statt Name eintragen
Verbindung kann nicht innerhalb des Zeitfensters hergestellt werden Datenbank nicht erreichbar, Firewall oder Port 3306 blockiert
Verbindungsaufbau wurde abgelehnt Datenbankdienst läuft nicht, oder der Benutzer darf nicht von diesem Rechner aus zugreifen
Ungültige Anmeldedaten Benutzer oder Kennwort falsch
Unbekannte Spalte in Tabelle Schemastand passt nicht zur Version — Versionsstände von Kasse und CentralPoint abgleichen

Proxy für den ERPSync-Dienst

Der Dienst ALVARAErpSync überträgt Lizenz- und Clouddaten. Er läuft als Java-Anwendung und übernimmt die Proxy-Einstellungen von Windows nicht automatisch. In Netzen mit Proxy schlägt er sonst mit Connection timed out fehl, es kommen keine Lizenzinformationen an und die Synchronisation mit der ERP-Cloud unterbleibt.

Die Proxy-Angaben werden dem Dienst als Startparameter mitgegeben:

-Dhttp.proxyHost=<Proxy>
-Dhttp.proxyPort=<Port>
-Dhttps.proxyHost=<Proxy>
-Dhttps.proxyPort=<Port>
-Dhttp.nonProxyHosts="localhost|127.0.0.1|*.local|10.*|172.*|192.168.*"

Der Dienst wird über NSSM verwaltet; die Parameter landen im Feld AppParameters. Zur Kontrolle steht derselbe Wert in der Registrierung unter HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\ALVARAErpSync\Parameters und muss dort vom Typ REG_EXPAND_SZ sein.

Danach den Dienst neu starten:

nssm restart ALVARAErpSync

Zur Prüfung: Die lizenzierten Module erscheinen im Lizenzbereich des Admin-Panels, und in C:\GoodCompany\Kasse\log\spring.log stehen keine Zeitüberschreitungen mehr.

[OFFEN: vollständiger NSSM-Aufruf zum Neuanlegen des Dienstes. Die vorliegende Quelle enthält an dieser Stelle ein Kennwort im Klartext und ist deshalb nicht übernehmbar.]
